## 实际执行

以下保留 2026-10-19 的原始验收方式；其中独立脚本已于 2026-10-22 迁移至 VS Code 任务，不再是当前启动命令。

1. `./scripts/Build.ps1`：使用 Qt 6.11.2、G++ 13.1.0、CMake 3.30.5、Ninja 1.12.1，Debug 配置和编译成功。
2. `./scripts/Test.ps1`：CTest 的 `startup`、`client_ui` 均通过；Python unittest 通过。检查包含中文/空格配置路径、缺文件、损坏 JSON、错误类型、不支持模式及未知字段，日志写入/失败，以及三种窗口显示状态。
3. 真实 `RM27_Client.exe` 分别使用嵌入默认配置、模拟示例配置、缺失配置启动：三个进程均持续运行，日志分别记录“正式”“模拟”“配置错误及绝对路径”。启动时没有模拟器进程。自动化检查后结束测试进程。
4. 真实 `python -m server.main` 在客户端关闭时独立常驻；检查后结束测试进程。`./scripts/Start-Simulator.ps1 -Check` 返回 0，并记录启动、检查和退出。

QML 测试使用 offscreen/software 后端加载真实窗口资源，检查模式、未连接、错误文本与回放禁用。真实入口检查验证了进程与日志，不等于已经完成操作手人工验收。

## 日志路径调整与复验

同日按用户要求，将客户端日志从 `%LOCALAPPDATA%/RM27/RM27_Client/logs/client.jsonl` 改为项目根目录下的 `logs/client.jsonl`。CMake 向客户端目标注入项目根目录字符串宏，主入口据此拼接路径；`.gitignore` 排除根目录 `logs/` 及散落的 `.log`、`.jsonl` 文件。

重新执行 Debug 构建、两项 CTest、三项 Python unittest，均通过。从系统临时目录启动真实客户端，确认日志追加在项目根目录，`git check-ignore` 确认忽略规则生效。旧 C 盘日志文件的删除被自动审批拒绝（`blocked by policy`），旧文件仍存在；当前程序不再写入旧路径。

代码、文件与完整运行过程说明见 [骨架结构与逐行解读](骨架结构与逐行解读.md)。

## VS Code 任务入口迁移（2026-10-22）

按用户要求删除四个独立 PowerShell 脚本，命令直接定义在 `.vscode/tasks.json`。配置和构建使用指定的 CMake，客户端任务直接启动 exe 并提供 Qt/MinGW PATH，模拟器和 Python 测试直接使用指定解释器。Task Buttons 保留原来的四组按钮，F5 的 `preLaunchTask` 仍指向 `RM27: Build Debug`。

迁移后按 tasks 中的程序、参数、工作目录、环境及依赖顺序实际执行：

- Debug、Release 各自完成配置、构建和两项 CTest；两套完整测试链都通过三项 Python unittest。
- 四种客户端启动组合（Debug/Release × 正式/模拟）均保持运行，项目日志中的模式正确；启动检查使用 offscreen 后端，检查后结束测试进程。
- 模拟器可独立常驻，`--check` 返回 0。
- 两种 launch 配置使用的 GDB 环境和参数均能命中 `main.cpp` 源码断点，模拟配置路径传递正确。
- JSON 任务名、依赖链、按钮绑定与调试前置任务检查通过，当前任务没有 `.ps1` 依赖。VS Code 状态栏点击本身未进行 UI 自动化验收。
