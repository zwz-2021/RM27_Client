# RMUC 2027 自定义终端客户端赛季规划

## 1. 战术定位分析

| 席位 | 场上要解决的问题 | 客户端的作用 | 效果 |
| --- | --- | --- | --- |
| 重装 | 操作手需要看清机械臂与科技核心的相对位置，在操纵机构的同时判断何时确认装配 | 有线控制器接入本队计算设备，主画面保留图传，同时显示装配步骤、科技核心状态、确认结果和 42 mm 发射机构权限 | 操作手能在同一席位完成操纵、装配与战斗状态切换。一次实物操作可以对应到机器人实际动作，一次装配请求可以对应到赛事结果 |
| 步兵 × 2 | 飞镖命中遮挡官方画面时，操作手仍需要观察前方，且双手要继续使用官方输入设备 | 自定义屏持续显示本机实际收到的新视频帧，以及血量、热量、允许发弹量等必要信息。 | 飞镖场景下能在自定义屏看到持续变化的现场画面，从开局到退出不各自发出的赛事业务消息 |
| 指挥手 | 单局比赛时间耗尽且双方基地均未被击毁时，优先比较累计控制度。指挥手需要知道哪处阵地正在争夺、哪些队友能支援、哨兵下一步去哪 | 地图突出剩余时间、阵地归属和控制度。叠加已知位置、人工标记与哨兵路径，提供哨兵干预、飞镖选靶与闸门状态 | 指挥手能判断支援方向、选对目标，并看出一次指令是成功、失败还是尚无结果 |

## 2. 核心研发功能点

### 重装自定义控制器接入

重装操作手通过队内有线控制器操纵机器人，同时在官方 HDMI 显示器上观察第一视角画面。客户端读取控制器输入，按机载端约定的格式写入 `CustomControl.data`，经官方图传链路以 `0x0311` 送达机器人。控制器拔除或连接中断时，客户端停止转发并清除待发输入，恢复后从操作手的新输入开始发送。

### 重装装配作业界面

操作手对准能量单元时，既要看清机械臂，也要知道科技核心是否到位。装配界面保留图传主画面，在旁边显示所选难度、科技核心状态和当前步骤，让操作手能看到能量单元是否已放入、平移或旋转。确认与取消入口就在图传旁。确认发出后先显示“等待结果”，收到裁判系统反馈再显示装配成功或具体失败原因。

### 步兵只读图传

两台步兵终端分别接收所属机器人的 H.265 图传，重组视频分片并优先显示最新有效帧，在画面边缘呈现血量、热量和剩余允许发弹量。飞镖命中使官方画面被遮挡时，只要自定义终端仍收到合法新帧，辅助屏就继续更新。视频中断时，屏上标明画面已失效。操作手全程使用官方端控车和发令，自定义终端只接收并显示数据。

### 指挥手战术地图

指挥地图围绕“哪处阵地正在争夺、哪台机器人能够支援”组织信息。地图突出阵地归属、争夺状态、双方累计控制度和剩余时间，叠加已知的机器人位置、哨兵规划路径和人工标记。位置图标带有信息来源和更新时间，使指挥手能区分刚收到的雷达位置、已经过期的观测和队友手动标出的位置。

### 哨兵干预与飞镖控制

指挥手从地图选择目标并发送标记，也可向哨兵发起补弹、复活或姿态切换。界面根据哨兵的自动或半自动模式提示干预费用，发令后显示执行结果，超时则保留“结果未知”。飞镖面板按操作顺序提供选靶、开闸和确认发射。指挥手能看到裁判系统返回的目标与闸门状态，待闸门完全开启，才在允许的发射窗口内确认发射。

## 3. 功能需求清单

### 3.1 核心模块清单

| 模块分类 | 功能项 | 描述 |
| --- | --- | --- |
| 公共通信 | 席位接入与重连 | 赛前配置席位、阵营及机器人 ID。断线后清空旧状态，重新订阅并收到与当前身份匹配的新数据后恢复显示。 |
| 公共通信 | 席位发送权限 | 在实际发送出口校验席位、身份、比赛阶段及指令类型。步兵允许订阅和必要的协议应答，全程赛事业务发布数为 0。重装和指挥手只发送各自获准的动作。 |
| 比赛数据 | 比赛状态与机器人资源 | 分别更新局号、阶段、剩余时间、血量、热量和允许发弹量。标记缺失和过期数据，区分有效的零值与尚未收到的值。 |
| 图传 | 视频接收与低延迟显示 | 将所属机器人的 UDP 视频分片重组为帧，解码 H.265，优先显示最新有效帧。损坏帧丢弃，限制缓存积压。 |
| 图传 | 飞镖遮挡与断流恢复 | 飞镖命中时继续呈现合法新帧。真正断流时标记画面失效，从后续可解帧恢复显示。黄牌、过热和后勤画质变化按各自规则处理。 |
| 重装操纵 | 自定义控制器采集与转发 | 读取有线控制器，按与机载端约定的格式写入 `CustomControl.data`，经图传送至机器人侧 `0x0311`。每包最多 60 字节，最高 75 Hz。 |
| 重装操纵 | 输入失效与停发 | 控制器拔除、失焦、断线或换席时停止转发并清理待发输入。恢复后使用新采样，机载端按双方约定执行失联处置。 |
| 重装作业 | 装配步骤与结果 | 同步可选难度、科技核心是否到位、能量单元放入、平移与旋转状态。开始、确认、取消分别使用赛事指令，依据返回结果更新进度。 |
| 重装战斗 | 42 mm 权限、补给与复活 | 分别读取发射机构使用权限、模块状态和成功安装事件。按资格及协议已明确的参数开放补给或复活请求，以实际资源变化或反馈更新结果。 |
| 指挥地图 | 阵地与控制度 | 汇总前哨阵地、基地阵地的归属与争夺情况，结合双方累计控制度和剩余时间呈现战局。 |
| 指挥地图 | 位置、路径与标记 | 分别处理机器人定位、雷达报告、哨兵规划路径和人工标记。保留位置来源与更新时间。按已明确的坐标基准、阵营和接收对象处理标记。 |
| 指挥交互 | 哨兵控制方式与干预 | 在规定的赛前窗口选择控制方式。赛中按对象、费用及条件发起补弹、回血、复活或姿态切换，按指令编号接收执行结果。 |
| 指挥交互 | 飞镖目标、闸门与发射 | 同步当前目标和闸门状态，将选靶、开闸、确认发射作为独立动作。恢复连接后重新读取当前状态，丢弃旧发射请求。 |
| 联调与发行 | 场景模拟与运行记录 | 独立模拟器提供状态变化、飞镖命中、拒绝、断线与视频中断场景。记录席位、版本、收发时间和异常，供软件、机载和操作手复盘同一场景。 |
| 联调与发行 | 比赛版本部署 | 用同一 Windows 发行包装载各席位配置，在目标机上独立启动。保留对应版本和配置，供现场恢复使用。 |

### 3.2 UI 界面需求清单

| 模块大类 | 界面子模块 | 核心功能 / 显示内容 | 操作规则 / 特殊说明 |
| --- | --- | --- | --- |
| 公共界面 | 席位与连接栏 | 当前席位、阵营、机器人编号、数据来源，以及赛事数据和视频各自的连接状态 | 赛前选择配置并连接。已连服务器但仍缺比赛数据时显示“等待数据”。更换席位后重新建立会话。 |
| 公共界面 | 比赛状态栏 | 局号、阶段、剩余时间、比分与关键事件 | 自动更新。缺值显示“—”，数据过期时标明状态，结算采用赛事引擎返回的结果。 |
| 公共界面 | 设备与链路诊断 | 当前席位适用的模块状态、视频最后更新时间、控制器连接情况 | 打开详情可区分赛事数据中断、视频断流和输入设备掉线。关闭详情只返回本地画面。 |
| 重装主界面 | HDMI 主视图 | 官方 1080p 屏以图传为主，边缘显示血量、热量、允许发弹量和控制器连接状态 | 操作手用队内有线控制器操纵。连接断开时显示“控制器已断开”，重新接入后等待新输入。 |
| 重装作业 | 装配面板 | 可选难度、科技核心到位状态、放入/平移/旋转步骤、确认结果 | 在图传旁选择难度、确认或取消。发出后显示“等待结果”，收到反馈再提示成功或具体失败原因。 |
| 重装战斗 | 发射机构与资源面板 | 42 mm 使用权限、模块状态、安装结果、己方经济、复活进度和可用补给 | 按资格启用相应按钮。费用、参数或结果未明确时给出当前状态，资源数值等待裁判系统更新。 |
| 步兵辅助屏 | 第一视角图传 | 每名步兵看到所属机器人的最新画面，主画面保持只读 | 飞镖命中时有新帧就继续显示。真断流时标明最后画面已过期，恢复后显示当前画面。控车始终在官方端完成。 |
| 步兵辅助屏 | 资源与事件提示 | 血量、热量、允许发弹量、性能选择结果、事件和适用限制 | 状态随消息刷新。点击、按键、失焦、退出或重连均不触发控车、兑换、复活、机关激活等赛事操作。 |
| 指挥主界面 | 阵地与控制度总览 | 大地图、阵地归属、争夺状态、双方累计控制度、比赛剩余时间 | 点选阵地查看详情。查看详情是本地操作，只有明确选择发送标记才向赛事引擎发令。 |
| 指挥主界面 | 机器人位置与哨兵路径 | 己方及已知敌方位置、来源、更新时间、人工标记和哨兵规划路径 | 点选对象查看来源。过期观测与当前定位采用不同样式，未获知的位置保留未知。 |
| 指挥交互 | 地图标记面板 | 标记类型、目标位置或机器人、接收范围 | 先选目标和接收对象，再点击发送。对象、坐标依据或席位权限不满足时禁用发送，标记以收到的同步信息更新。 |
| 指挥交互 | 哨兵面板 | 自动/半自动方式、姿态、资源、干预费用及指令结果 | 自动哨兵单次干预额外消耗 50 金币，半自动免额外干预费。购买或复活的费用另列。发出后显示等待、成功、失败或“结果未知”。 |
| 指挥交互 | 飞镖面板 | 当前目标、闸门关闭/开启中/已开启、可用操作 | 按规则选靶、开闸，闸门完全开启且处于允许窗口时才能确认发射。目标与闸门显示随权威同步更新。 |
| 指挥主界面 | 可用视频窗口 | 当前席位实际获准的视频来源及其有效画面 | 有合法图源时显示视频，断流时提示状态。地图、哨兵和飞镖面板仍按各自的数据与权限工作。 |
| 结算界面 | 本局结果与下一局 | 官方返回的局结果、两队比分和下一局状态 | 结算随官方结果显示。进入新局时清除上局标记、提示和待发请求。 |

## 4. 核心硬件选型

| 项目 | 建议配置 |
| --- | --- |
| 系统与处理器 | Windows 11 64 位，四核或以上的 x86-64 处理器，供图传、赛事数据和操作界面同时运行。 |
| 内存与存储 | 16 GB 内存，256 GB 或以上 SSD，为系统、客户端及联调日志留出空间。 |
| 图传解码 | 优先使用支持 H.265（HEVC）硬件解码的集成显卡，能持续处理一路 1920×1080、60 帧/秒的视频。核对具体型号的解码能力，并在实际驱动与客户端上试播。 |
| 网络与显示 | 千兆 RJ45 有线网口。重装和指挥手用 HDMI 输出到各自的官方 1080p 显示器，两名步兵使用笔记本自带的 1080p、60 Hz 或以上屏幕。重装机另留与队伍有线控制器匹配的接口。 |

## 5. 方案选型设计

### 5.1 技术选型

本项目采用 **Windows 原生桌面客户端**。重装、步兵和指挥席运行同一套程序，通过席位配置选用对应的工作台，共用赛事通信、状态管理和图传模块。

| 设计项 | 项目选型 | 选用理由 |
| --- | --- | --- |
| 程序与构建 | C++17、CMake | 协议解析、网络接入和会话管理分别编译为独立模块，由一个 Windows 可执行程序组合使用。 |
| 界面 | Qt 6、Qt Quick / QML | C++ 向界面提供可绑定的状态属性。三席可以分别布局重装作业画面、步兵只读屏和指挥地图，共用底层数据处理。 |
| 赛事数据 | MQTT 3.1.1、Eclipse Paho MQTT C 异步接口、Protobuf | Paho 负责连接与订阅，Protobuf 负责按官方消息定义读写二进制载荷。模拟器模式和官方模式复用同一个接收器，由配置选择服务器和机器人身份。 |
| 图传 | 独立的 UDP 接收与 HEVC/H.265 解码通路，接入 Qt Quick 显示 | 视频分片需要组帧和连续解码，单独处理可以限制积压、优先呈现最新有效帧。具体解码库和硬件加速方式在目标 Windows 电脑上确定。 |
