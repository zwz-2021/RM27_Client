# 08 测试方案与最终验收清单

表中证据与结论为 **2026-11-02 审计基线**，含更早留存的小范围检查，详见 [05 源码审计](05_Current_Gap_Analysis.md)。后续的实际验证、失败和未验证项记入 [13 进度日志](13_Progress_Log.md)。本页维护验收标准和复现条件。

## 分层验证和独立真值

| 层级 | 检查方式 | 证明范围 |
| --- | --- | --- |
| L0 | 原PDF字段/条款、实际调用链、配置版本、文档一致性 | 静态覆盖和偏差，不证明运行 |
| L1 | 手工字节/独立字段表、codec极值/坏包、策略/状态、UDP/组帧/解码源 | 不以共享proto和两端互通作为唯一预期 |
| L2 | 独立模拟器HTTP/Socket.IO、订阅抓实际MQTT/UDP、命令处理 | 不需Qt启动；网页改内存不算发送 |
| L3 | 网页→Broker→Qt状态/UI；Qt动作→模拟器→权威同步 | Qt必须真实参与，Python smoke不能代替 |
| L4 | 无开发环境Windows发行、官方接口/控制源/权限/码流、真实机器人 | 模拟器不代签，缺设备标未验证 |

32 种消息逐条核对 Topic、方向、字段编号和类型、optional 缺失与零、极值、频率和最高 QoS 1。AT-006/007/063 使用独立样本覆盖全部契约，AT-011/012/064 用实际席位配置检验收发；协议夹具和模拟器发出的消息单独标明来源。硬件指令由相应设备验证，桌面只经文档规定的接口收发。

### T-052 步兵 UDP 收包与包头诊断（2026-11-15）

- L1 以手写大端字节检查三个字段、0～7 字节短包、整包 1400/1401 和更长的数据报、65535→0。只有头或整帧长度小于本包数据的报文应单列丢弃原因。错误包保留上一次有效包头，停止后清空。按收到顺序展示原始片号。
- L2 分别从网页后端和命令行视频发送器取真实 UDP 报文，独立核对头、净长、整包上限和模拟源的回绕。
- L3 从正常产品窗口查看绑定端点、收包来源、计数及最近包头。检查绑定冲突时 MQTT 独立可用、MQTT 重连期间 UDP 独立收包、停止释放端口、新会话从零计数。组帧、视频画面和官方接入分别由 T-053..055、S10 验收。

### T-053 本机模拟源的分片重组（2026-11-16）

- L1 用手写字节在组帧器和实际 UDP socket 两处比对完整帧。覆盖倒序、重复、不同发送端使用同一帧号、65535→0、片内容或整帧长度冲突、极大声明和资源限额。只有片号从零连续且总字节数相符时才交付。停止后重用相同端口和帧号，旧分片不能进入新会话。
- L2 从网页后端和独立发送器抓取真实 UDP 数据。L3 用模拟配置启动产品窗口，检查最近完整帧、重复片、超时/冲突/超限丢帧和停止重开的读数。缺片后完全停止发包，窗口也应自行显示超时。在同一链路用模拟器发送已知帧数的视频，核对收齐帧数与最后一帧。
- L4 另采官方有线原始样本核对片号起点及码流边界。模拟器限定的组帧约定与工程预算记录在 [11 架构](11_Architecture.md)。

### T-054 本地 HEVC 软件解码小样（2026-11-16）

- L1 生成 1920×1080、60 fps 的已知 YUV 像素，经无损 HEVC 编码并包含 B 帧。按显示顺序比对解码后每一帧的尺寸、序号和像素摘要，包括文件结束时排出的末帧。分别给出真实切片截断与缺少参数集的样本，应有错误原因和非零退出码。
- 同一检查进程依次打开好、坏、好文件，再验指定帧数停止后打开仅有一帧的文件。每个文件独立计数，子进程退出后应能立即打开下一文件。个人录屏转换后的帧数按单独的媒体信息核对。
- 本段通过条件限于离线软件解码。L2 网络发送、L3 产品窗口视频播放、L4 官方码流和设备性能分别留给对应的后续验收。

### T-054 同一离线文件内的恢复（2026-11-17）

- L1 单次打开一份连续输入。两段均为无损 1080p60，源像素可区分，第二段带 VPS/SPS/PPS 及 IDR 关键帧。将第一段中间的一个普通切片截短，保留余下切片和第二段。工具须保留损坏诊断、继续输出并以非零退出码报告文件完整性。用第二段首帧的独有像素摘要定位恢复点，从该处至末帧逐帧核对序号、尺寸和像素。
- 对照文件分别在坏切片处结束、只缺所引用的 PPS。前者可保留前段输出并报告损坏，后者应无帧且诊断可追溯到所缺参数集。重开好文件应清空诊断，收到恢复帧后按帧数停止应保留已见错误。只从已知像素判定本地样本的恢复点。

### T-054 后台解码与像素帧所有权（2026-11-17）

- L1 从工具的正常启动入口打开已知无损短片。确认在调用线程之外交付完整像素，对收到的数据逐帧计算 SHA-256，与编码前的 Y、U、V 字节比对尺寸、顺序和末帧。
- 调用方只保留第一帧。收到不同像素的后续帧、提前停止并回收后台任务、重新打开另一段短片后，重新读取保存的像素应得到原摘要。新文件从序号 1 开始，坏文件的错误不会带入新文件。
- 用重复拼接的已知无损片段跨过 1000 个全尺寸帧，逐帧核对直到 EOF。另用整段录屏核对能持续交付像素并观察解码工具的内存。工具须继续接受原有启动参数，完成上面两段的损坏恢复和停止回归。模拟器发出的压缩帧接入解码器、产品窗口显示和官方设备分别留给后续验收。

### T-054 本机模拟器经 UDP 送入后台解码（2026-11-17）

- L1 用可区分的已知像素给出各帧预期，检查交付次序、尺寸和有限输入的末帧。验证等待输入同时受帧数和字节预算约束，停止、重开后旧输入及回调不能改变新会话的读数。
- L2 核对模拟发送器实际输出的分片。L3 用步兵模拟配置启动正常 Qt 窗口，让发送器经本机回环发送短片。分别核对收齐的压缩帧与解出的像素，检查停止、启动、再送一段可区分的视频；没有新输入时新会话应保持零帧。记录检查工具、实际输出顺序以及 Qt 窗口可观察的读数。
- 本段的产品结果是解码计数及像素尺寸。工作台实际显示画面归 AT-055，官方源片界和现场接入归 L4。

## 逐需求验收

### T-002/058 步兵只读配置保存与重开（2026-11-15）

- 用省略 `seat` 的个人 JSON 打开旧身份。停止接收，改选机器人并保存，核对其他设置及相对路径。占住目标文件使替换失败时，原文件字节和当前身份都应保留。释放文件可以重试。几个客户端先后保存同一文件时，过时的副本应提示重新打开。
- 在同一窗口重新启动接收，再用同一配置关闭重开。分别核对界面席位、配置机器人、静态报文身份及新血量，在隔离 Broker 按连接核对 CONNECT、五类订阅及零业务 PUBLISH。运行和等待重连时均应禁用编辑。现场权限另按 P-007 核验。

### T-035/012 步兵只读席位与身份展示（2026-11-15）

- L1 用配置和应用入口分别验证席位与机器人 ID 独立。省略席位、显式未指定、步兵、非法字符串及非字符串均有预期行为。正常连接、等待重连和停止时，步兵重复请求均应明确拒绝；原有数据和收包诊断应继续有效。
- L2/L3 使用隔离 Broker，分别观察 Qt 收到的消息与该客户端发出的包。读到五类新数据后，实际点工作台入口、按本地快捷键、切换窗口焦点、停止并恢复，核对可见席位、实收机器人身份、拒绝原因和最新血量。步兵连接的业务 PUBLISH 应为零，重新连接应继续订阅。
- 验收记录区分输入事件、业务拒绝、MQTT 连接包和数据报文。真实外设、其他席位的实际业务出口及官方分配的权限另验。正常入口与自动检查见 [12](12_Build_and_Run.md)，当前实测见 [13](13_Progress_Log.md)。

### T-013 五类只读接收的自动恢复（2026-11-14）

- 保持同一红方 3 号 Qt 进程，令五类数据均有值，再停止隔离 Broker。界面应进入“等待重连”，每类数据、身份和时效全部清空。以连续失败的连接尝试检查退避间隔增长和封顶，等待期间点停止或退出应取消后续尝试。
- 同一端口恢复服务，核对该客户端每次连接只有一个 CONNECT、对应身份、五条精确订阅和成功 SUBACK。按本页工程目标记录 Broker 恢复至重订就绪的耗时。仅恢复订阅时保持空值。新比赛报文可独立显示，无 ID 的消息等本次匹配静态身份和后续新报文。
- 独立记录该客户端发出的 PUBLISH 数，原连接、恢复连接和取消后均须为零。重装与指挥请求的不重放留到各自真实发布路径接入后验收。官方设备另验。脚本及报告见 [12](12_Build_and_Run.md) 和 [13](13_Progress_Log.md)。

### S2 首个五类接收切片（2026-11-04）

复现入口为 `scripts/check-basic-data.ps1 -SkipBuild` 与 `scripts/check-mqtt-receive.ps1 -SkipBuild`，后者使用独立临时端口，不复用或停止用户服务。实际结果与证据目录见 13。

- L1：保留五类独立字段表/固定字节及双向检查；追加状态的跨 Topic 更新、缺失/零、时间修正、身份门控、停止回调拒绝、配置错误检查。网络故障夹具独立核对 CONNECT 的十进制机器人 clientID、五条精确订阅及 QoS≤1。
- L2：复验现有模拟器基础发布和网页事件回执；本轮五类 schema、网页和发送器已具备所需入口，不为新链路另造私有业务。
- L3：真实 Qt 进程加载产品 QML，正常模拟器网页事件设置红 3/蓝 103 的 HP321、浮点热量及 uint64 最大经济，经 Broker 后核对界面和数组归属；HP322后可再次更新；停止即清空；连续100次启停。独立字节经真实 Broker 覆盖保留报文拒绝、坏包、缺失/零、身份错配、只停 Dynamic 时其过期且 Game 仍更新、恢复；订阅拒绝/连接超时/连接拒绝/订阅就绪但无数据不能显示比赛正常。另经正常 `scripts/run.ps1` 与实际浏览器操作复核可见页面。
- 身份与异常补充：同一批到达的静态 A→B→A 不得让B的无ID动态状态写入A；静态身份队列超限须失败清空。延迟末条SUBACK时，早到报文的缓冲时间必须计入新鲜度，旧HP不能因出队而变新；真实断开后清空并可手动再启动。
- 时效阈值为工程诊断：5/10Hz 的 Game/Dynamic 为1秒，三类1Hz消息为3秒，250ms检查；不是官方失联判定或业务规则。无ID的三类状态需本会话匹配且未过期的静态身份；单Broker同时混发多个机器人的数据不可据此获得可靠归属。
- L4：官方地址、终端网卡/身份权限和真实设备仍需现场验证；本地 AMQTT 不代签 Mosquitto 部署或官方接口。23条下行路由和完整需求验收不因五类切片通过而改为整项完成。

## 性能和稳定性门槛

以下是项目初始工程基线，非官方时延规定；开发机/目标机分别记录版本、硬件、解码方式、源/码率、配置。协议固定1080p60输入和消息频率不因工程目标而改写。

- 完整准备→自检→5秒→7分钟→结算→下一局至少一轮，另30分钟视频+输入+数据负载，零崩溃/死锁/挂起；启停100次零遗留worker/定时器，退出建议≤5秒。
- 实施前明确单帧/在途帧/总组帧内存/输出队列/日志容量的数值预算，验收实际峰值不得超预算；30分钟稳态无持续无界增长，不能只写“已优化”。
- 重装控制器在高频输入下检查 75Hz 上限、短期抖动和断线后的旧输入；13ms长期约76.9Hz不能当通过。步兵与同等视频/数据负载并行验证零业务 PUBLISH。指挥动作最高10Hz、地图按适用身份≥0.5/3秒分别抓包；单调时钟容差实施时固定记录。无发送端同步时钟不声称测得端到端控制延迟。
- 已知1080p60无丢包源30分钟，初始工程目标平均显示≥55fps、本地完整帧到提交显示P95≤100ms；记录解码/显示帧率、丢帧率与CPU/GPU/内存。未达到列性能缺口再优化，不暗降官方输入规格；官方端到端时延另用可对齐时钟/实机方法。
- 本地可控Broker恢复建议≤10秒完成重订阅；视频恢复后下一可解关键帧出现起建议≤2秒恢复画面，关键帧周期另记；官方环境另实测，缺关键帧时不承诺凭空恢复。
