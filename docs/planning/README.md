# RM27 自定义客户端开发入口

从这里选定一个可以独立验收的小任务。开发顺序看 [06 开发路线](06_Development_Roadmap.md)，实际进度和下一步看 [13 进度记录](13_Progress_Log.md)。固定规则和协议 PDF 仍存放在 [规则资料目录](../rules)，使用范围按 [项目约束](../../AGENTS.md) 执行。

自2026-11-07起，每次选任务先确定对应席位。**重装**用本队主客户端读取自定义控制器并发送 `CustomControl`，通过HDMI连接官方显示屏。**步兵**由官方端操控，本队终端全程只接收图传和状态，飞镖命中期间有合法新帧就持续显示。**指挥手**继续使用大地图、哨兵干预和飞镖等既定功能。开发顺序及每席通过条件见[路线中的席位表](06_Development_Roadmap.md#路线入口和版本)。

## 每轮开发

1. 从 [06 开发路线](06_Development_Roadmap.md) 和 [13 进度记录](13_Progress_Log.md) 选当前阶段的一小段。按 [07 任务表](07_Task_Backlog.md) 找到任务编号，再读 [02 需求](02_Requirements.md)、[03 协议矩阵](03_Protocol_Coverage.md) 和 [09 问题记录](09_Open_Questions.md) 中对应内容，核对实际源码。
2. 用 [12 构建、启动与排查](12_Build_and_Run.md) 准备环境，按 [08 测试与验收](08_Test_and_Acceptance.md) 检查这一小段。没有明确依据的字段或动作按 09 限定范围处理。只有离线或模拟器证据时，分别记录 Qt 网络、官方设备和实机的验证状态。
3. 把改动、启动命令、预期、实际结果、未验证项和下一步写入 13。发现文档疑问或有新的处理依据时更新 09。只有需求、任务或验收标准变化时才同步修改 02、07、08，已有的审计状态列用来追溯初始判断。
